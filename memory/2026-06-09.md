### 课程：第三方技能安装必须先安全审查

**时间**：2026年6月9日 下午（北京时间）

**事件**：在安装 anysearch-skill 时，我仅基于 GitHub 星数、更新时间和 README 外观进行判断，直接克隆仓库而未进行正式安全扫描。

**错误**：这违背了安全最佳实践。第三方 skill/plugin/MCP 工具不应仅凭表面指标安装，必须先审查代码、数据流向、依赖、许可证等风险点，并在安装前向用户报告潜在风险并等待确认。

**教训**：
1. 安装任何第三方技能前，必须执行安全审查流程：
   - 检查代码中是否存在危险函数（如 eval、exec、base64 解码、系统命令注入等）。
   - 明确数据发送目标和隐私声明。
   - 审查依赖隔离情况（零依赖或可审查的依赖更安全）。
   - 确认许可证声明（避免法律风险）。
   - 查看供应商透明度（是否有安全政策、漏洞报告渠道）。
2. 安装决策不能仅基于：
   - Star 数量（受欢迎程度不等于安全）。
   - 更新时间（最近更新不代表无风险）。
   - README 外观（文档质量与安全无直接关联）。
3. 必须先报告风险，再等待用户明确确认后才能执行安装。

**后续行动**：
- 已对已安装的 anysearch-skill 进行补救性安全审查（见下文）。
- 未来所有安装类任务将严格遵循“审查先行、报告风险、等待确认”的流程。

## 任何search-skill 补救安全审查结果

### ✅ 低风险项目
- 代码本体：审查 Python/Node.js/Shell CLI 脚本，未发现 `eval`、`exec`、`base64` 解码、混淆或可疑系统调用。
- 数据流向：明确发送到 `https://api.anysearch.com/mcp`，供应商声称零留存、无追踪、无日志。
- 依赖隔离：Node.js 和 Shell 版本零外部依赖；Python 版本仅需 `requests` 库。
- API 密钥处理：遵循最佳实践（CLI flag > .env > 环境变量 > 匿名访问）。
- 供应商透明度：由 `anysearch-ai` 组织维护，提供 `SECURITY.md`（含漏洞报告渠道和响应时间线）。

### ⚠️ 需注意的事项
- 许可证未明确：仓库中未看到 `LICENSE` 文件，README 和 SKILL.md 也未声明许可证。这意味着法律状态不明确（默认适用版权法）。
- 然而，该 skill 声明“无需 MCP 安装”，所有功能在封装的 CLI 中实现，无需审查后端服务器（降低攻击面）。

### 建议
- 短期使用：可以放心使用——代码审查无明显恶意特性，数据流向透明，供应商提供安全联络渠道。
- 长期依赖：建议联系仓库维护者 clarification 许可证事宜。
- 使用时：按文档建议将 API Key 存放在 `.env`（已在 `.gitignore` 中）或环境变量中；定期轮换 Key；涉及敏感查询考虑使用匿名访问。
