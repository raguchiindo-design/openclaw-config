# browser-lab

这个目录用于**隔离验证浏览器能力升级方案**，不直接等同于主 OpenClaw 生产环境。

## 目标
建立三层浏览器能力：
1. 云端默认浏览器层（当前 openclaw headless）
2. 云端增强浏览器实验层（本目录）
3. 本机真实浏览器 relay 层（高风控兜底）

## 使用原则
- 所有新浏览器方案先在这里验证，不直接进主环境
- 每个候选都要记录：依赖、体积、首跑下载、成功率、维护成本
- 优先追求：**先轻后重**、按需升级，而不是把重型浏览器变成默认层

## 目录结构
- `candidates/`：每个候选方案的评估卡
- `results/`：每次试装/试跑结果记录
- `templates/`：记录模板
- `venvs/`：本地隔离虚拟环境（可删可重建）
- `scripts/`：实验脚本

## 当前策略
### 优先级
1. 保留现有 `openclaw` browser 作为默认层
2. 在 browser-lab 中验证增强浏览器方案
3. Mac 真浏览器 relay 仅用于高风控站点兜底

### 当前判断
- `web-content-fetcher`：不建议进入主环境
- `jackwener/wechat-article-to-markdown`：方向对，但过重
- `x-reader`：实现偏薄，暂不作为重点投入对象

## 标准实验流程
1. 在 `candidates/` 新建候选卡
2. 在 `venvs/` 建独立 venv
3. 安装最小依赖
4. 对固定样例站点测试
5. 把结果写入 `results/`
6. 更新候选卡结论

## 固定测试问题
- 能否访问普通网页？
- 能否访问有轻度反爬页面？
- 能否访问微信公众号正文？
- 是否依赖超大下载？
- 是否必须真实浏览器/真实 IP 才有效？
- 维护成本是否可接受？

## 当前建议
短期不把重型反检测浏览器并入主 OpenClaw。
先用这里建立规范化实验体系，逐步减少对真机 relay 的依赖。
