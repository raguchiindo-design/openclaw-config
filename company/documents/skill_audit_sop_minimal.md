# Skill 审查极简 SOP（给未来任何 OpenClaw 模型）

目标：5 分钟内判断一个新 skill / MCP / 小工具，是否值得继续审、隔离试装，还是直接劝退。

## 一、先看 4 件事

1. **来源是否公开**
   - 有 GitHub / PyPI / npm / 官方文档
   - 能看到源码、依赖、许可证
   - 看不到源码的，默认高风险

2. **它解决的问题是否真存在**
   - 是否直接服务当前主任务：内容提取、趋势监控、发布、归档、连接器
   - 不是当前业务刚需的，优先级下降

3. **权限是否过重**
   - 要 sudo / 常驻后台 / 改系统服务 / 改 OpenClaw 核心配置 / 索要明文敏感凭证
   - 任一出现，先提高警惕

4. **是否有现成替代**
   - 先看 OpenClaw 现有工具、已有 skill、本地脚本能否解决
   - 能不用新安装就先不用

## 二、快速风险分级

### 直接劝退
- 黑盒服务端、无法审源码
- 要上传 token/cookie/私钥到第三方
- README 诱导 `curl | sh`、base64 执行、模糊安装命令
- 主要价值和当前业务无关

### 可继续审
- 开源
- 依赖不多
- 解决具体问题
- 无高权限要求

### 可隔离试装
- 仓库本体干净
- 依赖链可接受
- 但功能较重 / 维护成本较高 / 会引入额外联网能力

## 三、最小审查动作

1. 看仓库文件结构
2. 看 `README` / `SKILL.md` / `requirements` / `pyproject`
3. 搜危险模式：
   - `eval(` / `exec(`
   - `os.system`
   - `subprocess`
   - `curl` / `wget`
   - `base64`
   - 写入 `~/.openclaw`
   - 读取 `.env` / token / cookie
4. 看依赖是否：
   - 活跃维护
   - 来源公开
   - 许可证可接受
   - 体量是否明显超出需求
5. 看是否会产生隐藏网络行为
   - 额外 API
   - 自动下载浏览器
   - MCP server / telemetry / sponsor API / proxy API

## 四、安装决策

### 允许直接安装
- 依赖小
- 风险低
- 问题明确
- 有立即业务价值

### 只允许隔离试装
- 功能强但偏重
- 依赖复杂
- 可能影响主环境
- 先用 venv / 临时目录验证，不进生产

### 不装
- 风险高于收益
- 或现有方案已足够

## 五、隔离试装标准

1. 建独立 venv
2. 只安装最小依赖
3. 只测 3~5 个固定样例链接
4. 记录：
   - 是否成功
   - 提取质量
   - 是否额外联网/下载
   - 是否污染系统
   - 是否值得长期维护
5. 结论只写 3 种：
   - `可用，建议纳入`
   - `可用，但仅隔离使用`
   - `不建议采用`

## 六、默认优先级（当前这台 OpenClaw）

优先找：
- 微信公众号 / 社媒 / 网页正文提取
- 趋势监控 / 情报采集
- 发布自动化
- 表格/知识库/归档连接器

谨慎找：
- 反爬重型框架
- 需要浏览器全家桶的工具
- 黑盒 API skill
- 高权限常驻服务

## 七、针对微信公众号的当前原则

优先顺序：
1. 现有 `wechat-article-extractor`（镜像站方案）
2. OpenClaw 浏览器接管 / 已登录页面读取
3. 隔离试装轻量提取脚本
4. 不轻易把重型 scraping 框架并入主环境
